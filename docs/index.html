CLP em Python, lado a lado.

Cada trecho de Structured Text (CODESYS / IEC 61131-3) ao lado do Python equivalente. Mesma varredura, mesma semântica do eEstado := X — mais o que o CLP não dá: o motivo de cada transição, explain() e diagrama gerado do código.

Uma máquina completa

Estação de furação: um cilindro avança, a broca fura por 2 s, o cilindro recua. Se o cilindro demorar mais de 3 s, vai para FALHA. É o mesmo comportamento nos dois lados.

VAR_INPUT / OUTPUTviram uma IO (entradas) e atributos qx_* (saídas).
CASEvira um método @state(...) por estado.
eEstado := Xvira self.goto(X, "motivo").
eEstado <> eEstadoAntsome: a biblioteca detecta a troca e reinicia state_time.

Um ramo do CASE CASE · @state · timeout de passo

Cada estado vira um método. O watchdog de passo (tmrEstado.ET >= T#3S) vira timed_out(segundos).

state_time é o tmrEstado.ET em segundos. Um estado que você esquecer de declarar dá ConfigError na criação da máquina (ou liste-o em idle_states).

Trocar de estado eEstado := X · goto

É só uma atribuição: não encerra o ramo e não executa o novo estado agora. O motivo (opcional) vai para m.history.

Borda de subida R_TRIG · F_TRIG

Chame o bloco uma vez por varredura (em read_inputs()) e leia .q onde precisar, como o .Q do ST. FTrig é a borda de descida.

Timer TON TON · TOF · TP

O tempo é em segundos (T#2S vira 2.0). .q e .et são o .Q e o .ET do ST.

clock=self.clock liga o timer ao relógio da máquina. Nos testes você passa um relógio falso e avança o tempo sem sleep (veja Usar).

Saídas derivadas do estado write_outputs

A saída é função do estado, calculada depois do CASE. Se um override jogar a máquina em FALHA, a broca desliga sozinha: ninguém precisa lembrar de desligá-la.

Ao entrar no estado eEstado <> eEstadoAnt · on_entry

Roda uma vez, na primeira varredura depois de entrar, antes do ramo do estado. Também existem @on_exit(...) e on_state_change(old, new).

Na primeira varredura não há "entrada" do estado inicial, igual ao ST (eEstadoAnt começa igual a eEstado). Para disparar, crie a máquina com fire_initial_entry=True.

Latch SR / RS SR · RS

SR: o SET domina. RS: o RESET domina. Lê-se com .q (o .Q1 do ST).

Pedido com confirmação REQ → eco · Handshake

Mantém o pedido ligado a cada varredura até o outro lado ecoar de volta. Então volta ao valor ocioso e request() devolve True uma vez.

req_pedido.value é o que você escreve na saída para o outro lado; .active diz se há pedido pendente; .release() cancela.

IF/ELSIF longo vira tabela de decisão RuleSet · decide · explain

As pernas do ELSIF viram Rules em ordem de prioridade; a primeira verdadeira vence. Cada termo tem um rótulo, e & | ~ têm a mesma precedência de AND OR NOT do ST.

No CLP, descobrir por que a perna 2 não disparou exige ficar online olhando o ST. Aqui é uma linha:

[decisor] regra escolhida: falha
  1. falha -> FALHA  [+] ESCOLHIDA
  2. inicia -> PEDINDO_MATERIAL  [-] bloqueada por: NOT srFalha.Q

As condições precisam ser puras (só lêem): o explain() avalia todas as regras, inclusive as que perderam por prioridade. Rule(..., enabled=False) é o AND (FALSE) que se deixa no ST para desligar uma perna.

Override global depois do CASE after_case

Lógica que vale para qualquer estado (emergência, modo manual) roda depois do ramo. Se ela der goto, o último vence, como no ST.

Há também before_case(), para o que precisa rodar antes do ramo (por exemplo, travar um pulso que chegou).

A varredura

Cada scan() executa as 6 fases abaixo, sempre nesta ordem, como a task do CLP. Você só escreve as fases de que precisa.

  1. read_inputs()ler tags, atualizar R_TRIG e timers
  2. on_exit · on_entrytroca de estado (automático)
  3. before_case()antes do CASE
  4. @state(...)UM ramo: o do estado atual
  5. after_case()overrides globais
  6. write_outputs()escrever saídas
goto não é return

Depois do goto, o resto do ramo continua rodando, igual a eEstado := X;. Não escreva return por hábito.

Um ramo por varredura

goto(B) dentro de A não executa B agora: o novo estado só roda na próxima varredura.

O último goto vence

Um override em after_case() sobrepõe o que o ramo decidiu. O estado intermediário fica no history.

Cada bloco, uma vez por varredura

Chame RTrig, TON etc. só em read_inputs(); chamar duas vezes quebra a borda e o tempo, como no CLP.

Usar

Do zero até uma máquina rodando e testada.

  1. Instale 
    pip install git+https://github.com/tuliosalustiano27/MaquinaEstados_Python.git
  2. Escreva sua máquina

    Copie o exemplo completo acima, também em examples/minimo.py. Os outros padrões, rodando, estão em examples/padroes.py.

  3. Rode em ciclo

    run(m, period=0.05) varre a cada 50 ms. Aqui, só 3 varreduras:

    from examples.minimo import Furadeira, IO
from plcfsm import run

m = Furadeira(IO(ix_start=True))
run(m, period=0.05, max_scans=3)
print(m.state.name)
for t in m.history:                    # o que o CLP não conta: o porquê
    print(t.scan, t.src.name, "->", t.dst.name, t.reason)
    AVANCANDO
1 PARADO -> AVANCANDO start
  4. Teste sem hardware e sem dormir

    Passe um relógio falso e avance o tempo na mão, sem sleep.

    from examples.minimo import Furadeira, IO

t = [0.0]
m = Furadeira(IO(ix_start=True), clock=lambda: t[0])   # relógio falso

m.scan()                  # PARADO -> AVANCANDO
m.scan()                  # a entrada no estado é registrada aqui
t[0] += 3.0               # "passam" 3 s, sem dormir
m.scan()                  # o cilindro não chegou: FALHA
print(m.state.name, "|", m.history[-1].reason)
    FALHA | cilindro não avançou a tempo
  5. Analise sem executar

    O grafo sai do próprio código, sem declarar nada duas vezes.

    python -m plcfsm examples.minimo:Furadeira              # estados inalcançáveis / sem saída
python -m plcfsm examples.minimo:Furadeira --mermaid    # diagrama stateDiagram-v2
    Furadeira: 7 transições
inalcançáveis (0): -
sem saída própria (0): -

Limite: Python não é tempo real determinístico. Use para supervisão, coordenação, simulação, gêmeo digital e testes. Nunca como intertravamento de segurança.
